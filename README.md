# Semantifold

Task 044 proves the first packed JavaScript/JSDoc-to-Java watch workflow through Task 043's deterministic coordinator and Task 040's registry-driven check boundary. A credential-free consumer can keep `semantifold watch --check` running while edits regenerate Java and real `javac` commits coherent source/classes through one active pointer. Frontend or compiler failure retains the last good generation, a later valid edit recovers in the same process, and generated programs run only when acceptance code explicitly invokes real `java`. The package ships a [copy-ready watched project](examples/jsdoc-java-watch/).

Semantifold is an early language-neutral semantic code toolkit. The source tree supports a deliberately small fifteen-language baseline: PHP, Ruby, JavaScript with JSDoc, TypeScript, Java, Kotlin/JVM, strictly annotated Python, canonical C#, bounded Go, C17, C++20, Rust edition 2021, strict Swift, strict Dart VM/native, and strict Zig 0.15.2 source share one typed semantic representation. Browser WebAssembly is an additional target-only ID, not a sixteenth source language. Task 043 shipped through PR #58 at `40dcc86372929fb4747da08cd8e9d8226a32d88d`. The strict project manifest, one-shot and watched generation/publication CLI, generic non-executing check-plan contract, Java plus interpreted/managed target plans, deterministic watch coordinator, and packed JavaScript/JSDoc-to-Java vertical slice are implemented; native/project target plans and the terminal all-text-language matrix remain later tasks.

## Current API

```js
import {generate, parse} from "semantifold"

const module = parse({
  filename: "label.ts",
  language: "typescript",
  source: `
    function label(flag: boolean, fallback: string): string {
      if (flag) return "yes"
      else return fallback
    }
    console.log(label(true, "no"))
  `
})

const javaSource = generate({language: "java", module})
```

`parse` returns parser-independent discriminated semantic nodes with normalized types, source locations, a versioned source registry, and deterministic node/symbol provenance. `generate` accepts that shared module and returns an independently executable source program with its historical bytes unchanged. For each single-artifact target, `generateArtifact` adds an output filename, an authoritative range-based `SemantifoldMapping` v1, and a Source Map v3 sidecar:

Task 034 adds the explicit `createCapabilityAuthority(input)` boundary and optional `parse({capabilityAuthority, ...})` field. The helper validates, detaches, and deeply freezes a `SemantifoldCapabilityAuthority` schema-version-1 payload. It is compilation authority, not a source declaration or Task 035 standard-library contract version: an ordinary same-named function wins source resolution and cannot forge an effect. The returned single-module semantic graph contains deterministic capability/resource/failure/operation identities plus complete effect-site resolutions; `parseProgram` accepts the same optional authority so program modules may also declare the Task 035 canonical standard-library contract descriptor that `generateProgramArtifactSet` links against a negotiated target host provider set. `createStdlibContractRegistry`, `listStdlibModules`, and `resolveStdlibModule` expose the versioned canonical contract registry; `createStdlibProviderRegistry` and `listStdlibProviders` expose the target host provider registry; and `negotiateStdlibProviders` selects one stable compatible provider set for the transitive capability closure.

Task 036 adds `createStdlibFacadeRegistry`, `listStdlibFacades`, and `resolveStdlibFacade`. The built-in qualification corpus exposes one exact native-looking `compatibilityProbe(string): string` spelling per original-five source profile (snake case in PHP/Ruby), delegates through an internal executable facade module, and depends only on `semantifold.task034.resource-probe@1` operations `probeEffect` and `probeTrace`. `parseProgram` selects these definitions only from parser-proved native module plus symbol identity, records `SemantifoldStdlibFacadeResolution` evidence, and injects only the dependency-first reachable closure. `generateProgramArtifactSet` compiles those modules into collision-checked compatibility paths, marks them as support, preserves their source mappings, includes the complete `SemantifoldStdlibFacades` descriptor in link metadata, and validates the registry definition before returning any artifact. This is not general-purpose support for any of the fifteen languages. PHP, Ruby, JavaScript with JSDoc, TypeScript, and Java implement Task 005 general required functions/calls, Task 006 recursive immutable lists/maps, Task 007 explicit optional values, Task 008 ordered list iteration, Task 009 closed records, Task 010 explicit semantic projects, Task 011 typed unchecked errors, Task 012 invariant unbounded type parameters and generic declarations/applications, Task 014 insertion-ordered immutable map iteration, Task 032 strict-Boolean condition-controlled loops, Task 033 bounded reference classes, and Task 034's bounded effect/resource profile. Dart and Zig implement Task 005 general required functions/calls but none of those later profiles. `OptionalType {valueType}` contains only semantic presence or absence; it composes recursively as a declared list element or map value, and access preserves that optional result. A strict presence test can prove one simple binding present inside exactly the corresponding branch. Ruby uses exact `T?` metadata and `nil?`, JavaScript/JSDoc uses exact `T|null`, TypeScript uses exact `T | null`, PHP uses canonical `?T`, and Java uses exact `java.util.Optional<T>`/`Optional<T>` operations. Arbitrary unions, nested optionals, implicit nullable/default parameters, `undefined`, truthiness, nullish defaults/navigation, Java bare `null`, and unchecked unwrap remain unsupported. Collection support covers homogeneous literals, zero-based list indexing, total string-key map lookup, size, recursive typing, function passage, exact ordered list `for-each`, and the separate `OrderedMapType` pair-iteration profile. Ordinary `MapType` remains unordered and non-iterable. Ordered maps accept unique nonnumeric string keys, evaluate entries left-to-right, and visit key/value pairs in first-insertion order; aliases, mutation, key-only/value-only loops, and unordered conversions fail loudly. Java lowers only safe local ordered literals through a private `LinkedHashMap` insertion sequence and a non-escaping `Collections.unmodifiableSequencedMap` boundary. Every list, ordered-map, and condition-controlled loop has a deterministic semantic identity; each `break` or `continue` resolves to the nearest enclosing identity and cannot cross a function boundary. Collection loops evaluate their operand once and bind values immutably in body-local scope. A condition-controlled loop evaluates an exact Boolean condition before every iteration and may execute zero times; no loop body by itself proves a non-void function complete. Any outer mutable binding assigned on a nested loop path loses its known-value and optional-presence facts before the relevant repeated condition or body validation and after loop exit, including assignment paths ending in `break`, `continue`, or `return`; unaffected bindings keep stable facts. Task 007 does not turn an unchecked missing-key lookup into an optional operation. PHPDoc distinguishes `list<T>` from `array<string,T>`; JavaScript objects are never maps. Immutability is the accepted semantic operation boundary, not a deep-freezing promise. The other eight source languages and browser Wasm remain on the Tasks 001–004 two-parameter/scalar-return profile and reject later-feature modules transactionally. See [language support](docs/language-support.md) before using it on other code.

Task 009 models nominal product values as ordered `RecordDeclaration`/`RecordField` definitions, identity-bound `RecordType`, exact `RecordConstruction`, and resolved `MemberRead`. Records are closed and immutable: construction supplies every field once in declaration order, member access resolves to stable field identity, and structurally similar objects or maps are not records. Record declaration names cannot be captured by lexical parameters, locals, or iteration bindings. Presence-proven optional record receivers retain nominal field dispatch even when a field is named `length` or `size`, and Java zero-argument `equals()` record access remains distinct from one-argument string equality. Fields may recursively contain supported scalars, optionals, lists, maps, and records; an unmediated value cycle is rejected, while optional- or container-mediated recursion is accepted and compiled by every original-five target. Each frontend accepts only its documented canonical class shape. Backend preflight rejects target-reserved identifiers, including the deterministic PHP 8.2+ core/date/SPL/JSON type baseline and Ruby built-in type names, before emission; generated JavaScript and Ruby bind record freezing independently from user field and function names. Omitted or `undefined` external-IR `records` remains the legacy empty-record shape, while explicit `null` is malformed. Java uses a conventional final class with private-final storage, one constructor, and canonical accessors because pinned `@lezer/java@1.1.3` cannot faithfully represent Java `record` declarations. General classes, inheritance, interfaces/traits/mixins, extra methods, mutation, reflection, computed/dynamic members, decorators, equality/hashing, and copy/destructuring remain outside the profile. PR #34 delivered Task 009 after green TensorBuzz CI. This follow-up hardens JavaScript/Ruby record freezing and Java `equals()` member dispatch; its review and merge remain coordinator-owned.

Task 033 separately models closed nominal reference classes. Each class has deterministic declaration/member identities, ordered private fields, exactly one constructor that initializes every field once in declaration order, and exact instance methods. `ReferenceConstruction` allocates fresh identity; assignment and argument passage copy that reference, while private mutation remains available only through the semantic receiver in the declaring class. `MethodCallExpression` resolves nominally and evaluates its receiver before its left-to-right arguments. The original five accept one explicit parser-backed source profile and emit native class forms; every other registered role advertises `referenceClasses: false` and fails before artifact exposure. Inheritance, interfaces/traits/mixins, open classes or prototypes, overloads/virtual dispatch, reflection and lifecycle/protocol hooks, static members, public mutable fields, identity equality/hashing, finalizers, cloning/serialization, generic classes, and async methods remain excluded. Task 033 is single-module; both Task 010 program APIs reject class-bearing modules before resolution or output.

Task 034 adds `EffectCapabilityDeclaration`, `EffectCallExpression`, `OwnedResourceType`, `OwnedReferenceType`, explicit move/borrow nodes, declared nominal capability failures, and deterministic `effect:N` identities. Owned values may be direct immutable locals, parameters, returns, or the sole private owned field of an owned-reference class; they cannot be copied, reassigned, compared, serialized, nested in containers/optionals, or exposed through a field. Transfers require a move, borrows are immediate and nonescaping, and every reachable normal or failure path must close or transfer the owner. A borrow/read failure leaves the owner open; a close attempt is terminal even when close fails; subsequent use becomes the declared terminal failure without a second native operation. Optional absence represents only clean absence such as EOF and cannot absorb a typed host failure.

Only the exact unversioned `semantifold.task034.resource-probe` authority has built-in conformance bindings, on the original five. It exists to prove real acquisition/read/close semantics and left-to-right exactly-once lowering, not to expose files or sockets as public APIs. Backends preflight the complete capability/effect/resource graph before writer allocation and reject unsupported targets or arbitrary authorities transactionally. Async/concurrency/cancellation, `finally`/`ensure`/`defer`, implicit cleanup, RAII/destructors/finalizers/GC close, retry, general effect polymorphism, unsafe handles, shared mutable resources, and distributed transactions remain absent. Task 035's delivered hub adds versioned canonical standard-library contracts, the target host provider registry and protected native binding, capability negotiation, and program-mode provider linking with tree-shaken provider artifacts. Task 036 adds only the bounded neutral qualification facades; public file, socket, console, and other host APIs remain outside its scope.

Task 011 adds parser-neutral `ErrorDeclaration`/`ErrorType`, exact `ErrorConstruction` and `RaiseStatement`, one-handler `TryStatement`, immutable catch bindings, and `ErrorMessageRead`. A raise is abrupt completion; an exact matching handler consumes only that nominal identity, while every unmatched identity propagates. Internal fixed-point call-effect analysis establishes handler reachability without adding checked effects to public function signatures. Ruby uses empty `StandardError` subclasses and explicit typed `rescue`; JavaScript/TypeScript use empty `Error` subclasses plus an exact `instanceof` guard that rethrows unmatched values; PHP uses final `RuntimeException` subclasses and exact typed catches; Java uses final unchecked `RuntimeException` subclasses. Only the immutable string message is portable. Arbitrary values, broad/multiple catches, checked exceptions, causes/stacks, retry/rethrow, `finally`/`ensure`/`else`, resources, async rejection, result types, and non-original-five lowering remain unsupported. Generated single- and multi-file projects reparse to the same nominal identities; other targets advertise `typedErrors: false` and fail transactionally with `UNSUPPORTED_CAPABILITY`.

Task 012 adds declaration-owned `TypeParameter` identities, `TypeVariableReference`, exact generic record applications, and inferred type arguments on resolved direct calls. Inference is deterministic first-order unification from arguments only: a present value for `Optional<T>` contributes its contained value type, while an optional argument supplied directly for `T` contributes the complete `Optional` type. Empty collections and absent optionals, including those nested recursively in list/map literals, are contextually checked only after another argument or evidence-bearing nested value has resolved the same variable, independent of argument order. Complete substitutions apply recursively to call returns, constructor fields, and member reads; parser-known argument and explicit-application types provide only conservative frontend classification context, with the semantic validator remaining authoritative. Conflicts, missing variables, recursive substitutions, raw record use, and wrong arity fail with stable diagnostics; caller-supplied resolved signatures also require dense inferred type-argument arrays recursively through record identities. A non-generic record has no `arguments` member at all, and Java construction must spell every generic application rather than borrowing its local declaration. TypeScript and Java use native declaration/application syntax. JavaScript, Ruby, and PHP preserve the same contract through exact parser-associated documentation, including optional type variables and optional applied records nested in collections and maps. PHP closes recursive constructor context from parser-known sibling call evidence, including a present scalar supplied for `Optional<T>`, while retaining an open variable only when its exact parameter identity belongs to the caller's lexical declaration. PHP omits a native type only for `Optional<T>` when `T` has no faithful native carrier; fixed optional scalar, record, list, and map documentation instead requires the exact matching nullable native carrier, while nonoptional documentation rejects that marker. Its documented generic getter is admitted only on the exact record receiver, including a presence-proven optional receiver through an explicit semantic unwrap, while ordinary property access remains rejected. PHP otherwise uses private promoted storage and documented accessors for generic records so a direct type variable remains immutable without inventing a top type. No target substitutes `any`, `mixed`, `Object`, a raw type, specialization copies, runtime tests, or wrappers. Bounds/defaults, variance/wildcards, higher-kinded and conditional/mapped/indexed types, explicit generic function application, casts, reflection, and expected-return-only inference remain excluded. All other registered roles advertise `typeParametersAndGenerics: false` and reject generic IR transactionally. Task 013 is the terminal source-tree acceptance gate for the historical original-five Tasks 001–008 profile, delivered through PR 32 with its packed-consumer lifecycle correction in PR 33 on current `master`. Five substantial parser-native fixtures normalize to one complete semantic module, all 25 source→target routes validate and reparse equivalently, and byte-identical target outputs execute through real PHP, Ruby, Node.js, TypeScript/Node.js, and Java toolchains with exact results. Its comparator is spec-only and removes only source coordinates/provenance plus regenerated declaration identities. Semantic integers must be JavaScript-safe mathematical integers and have one unsigned zero. Generated JavaScript and TypeScript canonically render scalar output for modules containing negation or multiplication so IEEE-754 `-0` is observed as `0` without folding or rewriting the semantic operation tree. Java generation narrows literals and compile-time-known arithmetic trees further to signed 32-bit `int`. C# uses checked signed-64-bit arithmetic. Go uses exact decimal `int64` literals, rejects compile-time-known results outside signed 64-bit, and otherwise preserves native runtime wrap outside the portable guarantee. Strings are parser-decoded Unicode scalar values and are re-escaped for each target without preserving source quotes or escapes. Equality never coerces and never applies to objects or collections. Division, remainder, exponentiation, bitwise/shift/update/compound operations, ternary/nullish forms, general casts/assertions, truthiness, implicit returns, post-condition/basic/range/async loops, switches, exception behavior outside Task 011, and constant folding are unsupported. Task 006's exact TypeScript `Map#get(...)!` round-trip wrapper is the sole assertion exception and does not establish lookup totality. JavaScript and TypeScript functions must be synchronous and non-generator; Ruby annotations must be immediately associated comment blocks; and PHP accepts only an optional exact `declare(strict_types=1)`. ## Bounded standard-library portability

The `semantifold@0.6.0` baseline contains the delivered Task 035 canonical contract/provider hub and Task 036 bounded executable qualification facades; Task 037 is the source tree's first concrete Ruby-to-PHP TCP slice on those foundations. The design is hub-and-spoke, with two integrations per language: a source-facing **language compatibility stdlib/facade** preserves that language's familiar supported API shape in portable executable definitions, while a **target host provider/native binding** implements versioned **canonical Semantifold stdlib contracts/capabilities** with the target's genuine native standard library.

Ruby-to-PHP program generation compiles a Ruby application with portable Ruby `TCPSocket` and bounded one-string `puts`/`Kernel.puts` compatibility facades through semantic IR. The generated PHP retains those source-compatible names in a collision-safe compatibility namespace, calls canonical SocketClient, TextStream, Output, and Resource operations, and links only the required PHP provider modules. That protected provider uses native `fsockopen`, `fgets`, `feof`, and `fclose` for socket operations plus native stdout without adding a duplicate LF. This requires no handwritten Ruby-on-PHP bridge, source-specific loop recognition, or whole-program intelligent refactor. See the [authoritative standard-library portability design](docs/standard-library-portability.md) and [dependency-ordered implementation plan](docs/plans/2026-09-05-standard-library-portability.md).

## Development

Use Node.js 24 and install with `npm ci`. Specs use `@velocious/testing@0.0.0` and the standalone `velocious-test` runner. Run a focused spec with `npx velocious-test spec/repository-contract.spec.js`. Task021 local validation runs explicitly named changed/affected spec files sequentially; aggregate `npm test` discovery runs only in TensorBuzz.

The aggregate suite includes direct real-toolchain specs that inherit the outer test process locale, so repository validation requires `LANG=C.UTF-8` and `LC_ALL=C.UTF-8`. The canonical container currently exports neither variable. This outer-suite requirement is separate from `runAcceptanceStages`, which normalizes the locale and timezone of every child it owns and does not depend on ambient locale.

The local quality/package gate follows the named focused specs documented in [testing](docs/testing.md):

```sh
export LANG=C.UTF-8
export LC_ALL=C.UTF-8
npm run verify:legacy-runtime
npx velocious-test spec/repository-contract.spec.js
npm run lint
npm run typecheck
npm run build
npm audit --audit-level=high
npm ls --omit=dev --all
npm ls --all
npm pack --dry-run --json
git diff --check
```

The root distribution explicitly bundles root `tree-sitter@0.25.1` and a private internal package containing an isolated exact `tree-sitter@0.21.1` plus `tree-sitter-c@0.23.2`, `tree-sitter-cpp@0.23.4`, and `tree-sitter-rust@0.23.1` dependency subtree. The immutable Kotlin grammar remains an ordinary full-SHA HTTPS source-archive dependency. The private `packages/tree-sitter-legacy` workspace owns source checking and declaration generation, but has no export or publication identity. Its serializer returns only recursively frozen parser-neutral CST data; native parser, tree, node, and language handles stay inside the legacy runtime. The packed-consumer spec installs the real root tarball with a fresh npm cache and proves modern Kotlin/Go and legacy C/CPP/Rust parsing together without a workspace, SSH route, or registry fallback for the internal package.

Because `install-links=true` installs a copy of the private runtime, run `npm ci` again after editing its shipped files under `packages/tree-sitter-legacy/runtime/`. Tests, lint, and `npm pack` reject a stale installed payload with that recovery instruction. The gate compares npm's source file inventory and every file's bytes, including the manifest, serializer, README, and license; it never copies or repairs dependencies itself.

Consumers need no Semantifold-specific npm settings: default `npm install`, `npm ls --all`, and subsequent `npm ci` work with `install-links=false`. The repository alone uses `install-links=true` to materialize the local source. Root `acceptDependencies` accepts only the exact private `0.1.0` package already present in the bundle; npm resolves the Kotlin grammar from its integrity-locked full-SHA HTTPS source archive. The cold-consumer proof isolates user/global configuration, verifies the public registry and ordinary default, rejects SSH lock entries, and repeats dependency, parser, TypeScript, Rust, and Kotlin/JVM checks after both install and clean reinstall.

The execution specs require PHP CLI, Ruby, Python 3, TypeScript, a Java JDK, Kotlin/JVM 2.4.20, .NET 10, Clang 21.1.8 with compiler-rt, Go 1.26 with matching `gofmt`, the exact qualified Rust/Cargo 1.98.1 pair, Swift 6.3.3, Dart SDK 3.13.3, Zig 0.15.2, WABT 1.0.36, and headless Chrome/Chromium 152.0.7977.82 in addition to Node; missing tools are failures. The canonical container contract installs Kotlin, Java, Dart, and Zig during image construction; runtime tests never download a compiler or dependency.
