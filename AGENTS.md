# Repository instructions

Semantifold is an ESM JavaScript package with strict JSDoc typing. Keep parser-specific trees inside `src/frontends/`; public values use only the semantic types in `src/semantic/types.js`. Keep target syntax inside `src/backends/` and fail with a `SemantifoldDiagnostic` when source syntax or backend capabilities exceed the implemented subset. Never add source-text parsing fallbacks when a parser adapter rejects a construct.

Every behavior change needs a focused spec and matching documentation. Use one top-level `describe` per spec file. Runtime-generation coverage must invoke real `php`, `ruby`, `node`, `tsc`, `javac`, and `java` commands and must fail if a command is unavailable. Do not replace these checks with snapshots or source-only assertions.

`build/` is generated by `npm run build`; never edit it manually. It is gitignored and produced for npm packaging. Add changelog fragments under `changelog.d/YYYYMMDDHHMMSS-short-slug.md`.

The root `Dockerfile` and `compose.yml` are the only canonical development-container artifacts. The canonical Compose service is `dev`. The image remains source-independent: do not add project `COPY`, dependency installation, provider CLIs, or orchestration coupling. Compose owns exactly the complete `/home/dev` bind and the read-only GitHub CLI configuration bind. This repository has no database, cache, or support service.

From the repository root, start and validate the canonical lane with this portable sequence. The defaults resolve the repository's parent development home and the host GitHub CLI configuration; export either path in advance when the host layout differs.

```sh
export DEV_HOME_PATH="${DEV_HOME_PATH:-$(cd .. && pwd -P)}"
export GH_CONFIG_SOURCE_PATH="${GH_CONFIG_SOURCE_PATH:-${XDG_CONFIG_HOME:-$HOME/.config}/gh}"
docker compose -p semantifold-dev -f compose.yml up --build --detach
docker compose -p semantifold-dev -f compose.yml exec dev npm ci
docker compose -p semantifold-dev -f compose.yml exec dev node --test spec/repository-contract-spec.js
docker compose -p semantifold-dev -f compose.yml exec dev npm test
docker compose -p semantifold-dev -f compose.yml exec dev npm run lint
docker compose -p semantifold-dev -f compose.yml exec dev npm run typecheck
docker compose -p semantifold-dev -f compose.yml exec dev npm run build
docker compose -p semantifold-dev -f compose.yml exec dev npm audit --audit-level=high
docker compose -p semantifold-dev -f compose.yml exec dev npm ls --omit=dev --all
docker compose -p semantifold-dev -f compose.yml exec dev npm pack --dry-run --json
docker compose -p semantifold-dev -f compose.yml exec dev git diff --check
```

Focused behavior specs use the same prefix and an exact spec path, as shown by the repository-contract command above. Host and orchestrator preparation is outside this repository; non-Hermes environments keep and operate their own setup rather than adding provider or orchestration coupling here.

TensorBuzz is the only CI topology. Do not add GitHub Actions. Before handing off changes, run:

1. `npm test`
2. `npm run lint`
3. `npm run typecheck`
4. `npm run build`
5. `npm audit --audit-level=high`
6. `npm ls --omit=dev --all`
7. `npm pack --dry-run --json`
8. `git diff --check`

Do not manually edit generated declaration or build files.

The delivery route is local focused and aggregate validation, then the already-bounded independent review, followed by TensorBuzz CI for the exact candidate head with webhook monitoring through completion. After an exact-head green result, merge through the coordinator-owned workflow. Run an npm release only when separately requested, then verify the live package from the public registry and reconcile the completed work with the owning task. Review, CI, merge, publication, and external task mutation remain coordinator-owned unless explicitly delegated.
