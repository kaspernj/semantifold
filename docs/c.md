# C source and native target profile

Task 018 implements the existing Tasks 001–004 semantic subset as independent language `c`. Use `parse({language: "c", filename, source})` and `generateArtifactSet({language: "c", module})`. Generation returns mapped `program.c` first and synthetic support artifact `semantifold_runtime.h` second, with deterministic LF content. Only an omitted filename or exact `program.c` is accepted. Mapping filename/directive options are rejected. Single-artifact generation reports `UNSUPPORTED_ROLE`; C has no binary-backend, interoperability, project-graph, or FFI role.

## Scalars, arithmetic and lifetime

| Semantic value | Exact C representation | Rules |
| --- | --- | --- |
| `integer` | `int64_t` | Safe nonnegative decimal literal payloads; negative values are unary negation. Generated literals use `INT64_C`. |
| `boolean` | `bool` | Exact `true`/`false`; no integer conversion or truthiness. |
| `string` | `SemantifoldString` | Immutable `const unsigned char *data` plus `size_t length`, containing valid UTF-8 bytes including embedded NUL. |

The qualified ABI is Linux x86-64: eight-bit bytes, 64-bit `int64_t` and `size_t`, `PTRDIFF_MAX == INT64_MAX`, and eight bytes of arena metadata per allocation. Header static assertions enforce these assumptions at compilation. Caller identifiers begin with an ASCII letter and continue with ASCII letters, digits or underscores. C keywords, imported standard-header names/types/macros, implementation-reserved names, and the `semantifold_`, `SEMANTIFOLD_` and `Semantifold` namespaces are protected in both directions; generation never renames a collision.

Boolean literals must have exact lowercase `true`/`false` spelling. The frozen grammar also classifies `TRUE`/`FALSE` expression tokens as Booleans, so those uppercase spellings are rejected as both expressions and caller identifiers, including parameters, locals and functions. They are not aliases or implicit constants. The imported `<limits.h>` macro `MB_LEN_MAX` is also reserved in both directions; a target collision receives a located `UNSUPPORTED_CAPABILITY` before any artifact is returned.

Every add, subtract, multiply and negate uses a checked helper. Clang overflow builtins detect signed-64-bit overflow without evaluating undefined signed arithmetic; negation is checked subtraction from zero. Known literal arithmetic outside signed 64-bit is rejected with `UNSUPPORTED_CAPABILITY` before generation. Dynamic overflow cleans the arena, writes exactly `semantifold: integer overflow\n` to stderr and exits with status 70. This is a target failure boundary outside semantic user control; it does not add exceptions or wider portable integer guarantees to the IR. `INT64_MIN` prints correctly using unsigned magnitude conversion. A negative or negative-zero `IntegerLiteral` payload is rejected; unary negation remains a supported operation.

`SEMANTIFOLD_STRING("...")` borrows a static C string-literal array, excluding its terminating byte by `sizeof(literal) - 1`. The strict C17 profile limits each decoded literal to 4095 UTF-8 bytes; larger literal objects fail before artifacts. Runtime concatenations can exceed that literal translation limit. Generated tokens encode each UTF-8 byte with three-digit octal escapes, avoiding locale changes, escape munching and embedded-NUL truncation. The frontend decodes only parser-owned ordinary string content and valid simple/octal/hex byte escapes, then verifies complete UTF-8. Copies, parameter passing and returns copy only the descriptor. They do not allocate, mutate, transfer ownership, or end the underlying lifetime.

A hexadecimal escape must end at the same boundary in C and the parser. The frozen grammar consumes at most four hex digits per escape node, while C consumes every following hex digit. An escape followed immediately by a parser-owned content node starting with another hex digit is therefore rejected with located `UNSUPPORTED_SYNTAX`, even if its numeric value would fit in a byte. For example, `"\x000041"` is rejected rather than decoded as NUL plus `41`; native C produces `A`. Bounded byte escapes such as `"\x41"`, `"\x0041"` and `"\x43G"`, separate escaped UTF-8 bytes, octal escapes and embedded NUL remain supported. No source reparsing or dependency modification repairs a split escape.

Each concatenation allocates one arena node, including empty concatenations. The requested object contains the metadata plus exactly the two explicit byte lengths; it does not require a string terminator. Before allocation, the header checks each length, their sum, metadata addition and cumulative arena accounting against `PTRDIFF_MAX`. It then checks `malloc`, links the owned node and copies nonempty byte ranges. Known literal/local length growth and known allocation lower bounds receive corresponding preflight checks without rewriting the semantic IR. Unknown lengths remain checked at runtime. Size failure writes `semantifold: allocation size\n`; allocation failure writes `semantifold: allocation failure\n`. Both clean existing allocations and exit 70.

Canonical `main` calls `semantifold_cleanup()` once after semantic entry statements and returns zero. Cleanup frees each owned node and clears the arena. Returned slices and branch-local descriptor copies therefore remain valid until entry completion. The same cleanup runs before every generated fatal exit. No allocation hook, pointer operation, free, lifetime choice or ownership state is exposed to portable code. Printing uses `fwrite` with explicit lengths, canonical ASCII integer/boolean formatting and one LF. Output failure follows the same fatal policy with `semantifold: output failure\n`; stdout is flushed after each print.

## Accepted source and complete CST validation

The unchanged root-bundled private legacy boundary supplies recursively frozen C CST data from exact `tree-sitter@0.21.1` and `tree-sitter-c@0.23.2`. `src/frontends/c-parser.js` describes that private plain-data boundary; native handles and parser-specific objects never enter semantic values. Every child, field, anonymous token, extra, error, missing node and recovery flag is traversed before meaning is returned. Coordinates and token origins refer to the original UTF-16 source, including astral characters and CRLF. There is no parser-source scan, compiler-based interpretation, preprocessing fallback or source-text recovery.

Ordinary source contains the exact support-header include, at least one `static` semantic function with two named explicitly typed parameters, and final `int main(void)`. Functions return exact scalars. Bodies admit initialized single scalar locals, plain assignment, prints through the matching scalar helper, explicit returns and braced conditionals, including `else if`. `const` locals are immutable; other locals are mutable, and parameters are immutable. Main ends with the exact cleanup call and `return 0`. Raw calls must refer to a preceding or current function definition. Caller-authored forward calls requiring implicit C declarations are rejected; canonical generated prototypes support forward calls and recursion.

Only direct semantic calls and the exact scalar/literal/print helpers are recognized. Caller-authored calls nested in an operator operand or another call's argument are rejected because ordinary C does not establish the required semantic evaluation order. Trigraph preprocessing in parser-backed comments or string content is rejected. No user preprocessing, typedef substitution, global data, complex/multiple declarator, qualifier beyond local `const`, array, struct, union, enum, pointer, function pointer, cast, address/dereference, member access, ownership call, `sizeof`, comma/ternary, loop, switch, goto, update, compound operator, conversion or arbitrary external call is accepted.

Before discarding any parser-backed comment, the frontend rejects backslash-line-ending splices and line comments containing content after a lone CR. The pinned parser can otherwise hide text that native C executes, including a statement following `// comment` plus a bare CR or a block-comment terminator split by backslash-newline. This validation precedes semantic extraction and generated-region comparison. Ordinary line/block comments, exact generated markers, and normal CRLF remain supported and execute under the same strict compiler profile. A split comment opener that the grammar already rejects remains a located `PARSE_ERROR`; compiler output is never used to recover source meaning.

## Ordered expressions and exact reparse

After complete semantic/target validation and before creating a writer, the C backend plans each expression occurrence in semantic left-to-right order. It treats every call as potentially observable. Each call and enclosing nontrivial operation gets its exact scalar type and a consecutive six-digit name such as `semantifold_ordered_000001`. Eager left preludes precede right preludes. Short-circuit results receive a temporary initialized from the left value, an exact conditional RHS prelude and one final result write using the original `&&` or `||` operator. That token retains the original operator mapping; the generated conditional and temporary names are synthetic. The pure result then feeds the original local initializer, assignment, return, print or conditional test. Branches recursively contain their own regions. The public IR is never rewritten.

Every semantic statement is surrounded by exact paired comments:

```c
/* semantifold:ordered-expression:c:v1 begin 000001 <64 lowercase hex digits> */
/* semantifold:ordered-expression:c:v1 end 000001 <same digest> */
```

The digest is SHA-256 over the closed consumer/expression signature implemented in `c-ordered-expressions.js`, excluding locations. It detects changed operators/consumers; it is not an authentication mechanism or a substitute for tree validation. Generated files start with exact `/* semantifold:program:c:v1 */`, followed by the include, matching ordered prototypes, semantic definitions and main. Exact generated `(void)name;` uses prevent warnings for unused functions, parameters and locals; they are accepted only at their canonical positions.

The frontend first reconstructs a private candidate from complete region child lists and direct temporary references, requiring each temporary to be consumed exactly once and rejecting duplicate declarations, extra reads and dead values before shared validation. The candidate must also meet the C graph/occurrence bounds. It then resolves semantic types, regenerates the canonical plan, parses that candidate C through the same CST boundary and compares the **entire original CST** against the canonical CST. Every significant node type, child count, field, token, marker, temporary type/number, initializer, dependency, conditional RHS, write, consumer, prototype and discard position must agree. Only ordinary comments and whitespace are ignored. No candidate module escapes before this comparison. Generated programs must use the complete canonical profile; isolated marker fragments or mixed ordinary/generated statements are rejected.

Missing, duplicated, reordered, forged or wrong-version markers; extra/dead/escaping temporaries; wrong types/operators/consumers; altered scaffold casts/prototypes; and malformed semantic content inside a generated region all report located `UNSUPPORTED_SYNTAX`. Parser recovery remains `PARSE_ERROR`. Backend malformed IR, collisions, invalid required locations, cycles, target bounds and unsupported options report `UNSUPPORTED_CAPABILITY`. The unchanged legacy parser accepts at most 32,767 UTF-16 code units per source input; a direct real-parser boundary test proves success at 32,767 and its native failure at 32,768. The C frontend gives a located size diagnostic, and the backend performs an exact output-length preflight before constructing the provenance writer or exposing artifacts. It rejects generated programs above that same limit. No buffer override, parser-payload change or source trimming bypasses this boundary. The bounded C plan also rejects semantic graph depth above 512 or more than 999,999 expanded graph occurrences before recursive validation/emission; occurrence names and statement IDs never widen or wrap.

Rich mappings and Source Map v3 retain original operator, call, literal, binding and final-consumer origins. All generated declarations/names/markers, prototypes, unused-binding uses, short-circuit control and cleanup are synthetic with related semantic origins. Shared IR objects receive distinct occurrence paths, temporary names and map records. The header is a synthetic artifact related to the module root.
