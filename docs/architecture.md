# Architecture

Semantifold has three explicit layers.

Task 018's C path follows these layers through the unchanged root-bundled private legacy CST boundary. `src/frontends/c.js` owns all C trees and exhaustive profile validation. `src/backends/native-validation.js` checks native graph/location limits and `c-validation.js` checks C memory limits; `ordered-expressions.js` plans occurrence-specific evaluation without modifying IR; `c.js` emits mapped `program.c`; and `c-runtime.js` supplies the synthetic immutable-slice/arena header. The C frontend reconstructs candidates only from complete CST regions, resolves them with the existing semantic validator, and compares the original whole CST against the re-parsed canonical backend plan before returning a module. This same-language validation keeps target generation free of parser objects. See the [C profile](c.md).

1. Frontend adapters in `src/frontends/` invoke mature language parsers and translate only recognized syntax. Babel owns JavaScript and TypeScript parsing, `php-parser` owns PHP, Prism owns Ruby, Lezer owns Java, and qualified Tree-sitter bindings and grammars own Python, C#, Go, C, CPP, Rust, Swift, and Kotlin. Their AST/CST objects never appear in the public API. Adapters enumerate supported children and reject every other parser node; filtering syntax away is not a normalization strategy. Prism node offsets and comment byte ranges are converted from UTF-8 to JavaScript UTF-16 offsets before semantic location construction and metadata source slicing. Tree-sitter adapters reject lone surrogates, exhaustively traverse named/anonymous/comment/directive/error/missing children, and verify reported boundaries through the shared UTF-8-byte-to-UTF-16 converter. The Go adapter additionally collapses only exact `package main`, optional `fmt`, ordered semantic functions, and a final zero-argument `func main()` into the shared module/entry shape; assignment occurrences, not Go's uniformly mutable `var` syntax, determine semantic local mutability.
2. `src/semantic/` defines the shared JSDoc-typed discriminated representation and one-based, filename-bearing UTF-16 source locations. `provenance.js` indexes exact source content, deterministic semantic paths/node IDs, resolved symbol IDs, parser-token subranges, and closed source/derived/synthetic origins without exposing parser objects. Task 010's `SemanticProgram` adds dependency-first logical modules, a caller-order multi-source registry, explicit import/export nodes, one selected entry module, and stable module-qualified declaration identities; native filenames, package names, and target paths remain outside semantic resolution. Value types are scalar `integer`/`boolean`/`string` references or recursive acyclic `ListType`, string-keyed `MapType`, `OptionalType`, and nominal `RecordType`; `void` exists only as a function return. Task 012 adds invariant unbounded declaration-owned `TypeParameter` values, scoped `TypeVariableReference` leaves, and exact ordered arguments on generic record types. Task 011 adds nominal `ErrorType` only for catch bindings and error constructions, never as an ordinary parameter/local/return value. Every function has a deterministic declaration identity. Every direct call retains its source spelling and a `ResolvedFunctionSignature` containing the declaration identity, ordered recursive parameter types, value-or-void return type, and complete inferred type arguments for generic declarations. Literal and access nodes distinguish scalars, lists, maps, presence/absence, total list/map lookup, finite collection size, and the sole portable error member `message`. Unary and binary expressions carry a closed semantic `operation` and explicit result `type`, never a source operator symbol. Every function, entry point, branch, loop, try body, and catch body owns a located `Block` containing ordered `Statement` nodes. Statements additionally include exact `RaiseStatement` and one-handler `TryStatement`; map iteration and general exception constructs have no semantic node. `ReturnStatement.expression` is present exactly for value returns. Source-spelled `else if`, `elsif`, and `elseif` normalize to an alternate block containing one nested conditional.
3. Source and binary backends in `src/backends/` validate their semantic capabilities before emitting target syntax or bytes. Shared validation owns recursive block shape, reachability and all-path abrupt-completion analysis, recursively complete expressions, exhaustive operation/type signatures, function signatures, lexical binding scopes, mutability, declaration-before-use, strict condition/return/argument/initializer/assignment types, and fixed-point propagation of nominal unchecked errors through direct calls. Dependency-first Task 010 validation carries those inferred sets across resolved function-import identities, including transitive helpers. That effect analysis is validator state, not a checked-effect list in the public function signature or serialized IR. Target-specific validation adds identifier rules, entry-scaffolding name collisions, numeric/memory/resource bounds, and target string representation. Text emitters write through `SourceWriter`; the Wasm encoder writes through an annotated binary writer so every byte range is semantic or explicitly synthetic. A backend either returns a complete executable program/project/application set or raises `UNSUPPORTED_CAPABILITY`; it never silently drops nodes, exposes a partial artifact, or lets an emitter discover malformed shape through a native error.

`src/language-registry.js` is the sole ordered dispatch and discovery source. Its deeply frozen records bind implementations to independent frontend, text-backend, binary-backend, application-backend, and interoperability roles. Public descriptors derive role booleans, semantic feature flags, artifact multiplicity, round-trip support, rich/v3/byte mapping forms, and acceptance stages/toolchains from those records; `generalFunctionsAndCalls`, `immutableCollections`, `optionalValues`, `orderedListIteration`, `closedRecords`, `typedErrors`, and `typeParametersAndGenerics` are true only for PHP, Ruby, JavaScript, TypeScript, and Java. `supportedLanguages` is the derived compatibility view containing IDs with both a frontend and text backend. Duplicate IDs, unknown record fields, malformed capabilities, and unordered acceptance stages fail as `INVALID_REGISTRY`.

`index.js` is the public boundary. `parse({language, filename, source})` resolves only the frontend role. `parseProgram(...)` composes only the original-five parser adapters over an explicit complete source set, resolves declarations by identity, and performs no I/O. `generate({language, module})` and `generateArtifact(...)` resolve a single-text backend, validate the full module, and preserve the compatibility source/artifact contracts; they intentionally reject the multiple-artifact C#, Go, C, Rust, and Wasm backends. `generateArtifactSet(...)` remains the additive single-module artifact boundary, while `generateProgramArtifactSet(...)` plans and validates a complete original-five program before any writer allocation. An unknown ID is `UNSUPPORTED_LANGUAGE`; a known ID missing the program cohort is `UNSUPPORTED_ROLE`; `UNSUPPORTED_CAPABILITY` remains a backend-with-role rejection of semantic content or target layout. `src/artifacts.js` owns transactional generated-file validation and detached, deeply frozen JSON metadata snapshots, including JSON object keys without prototype interpretation. `src/binary-mapping.js` owns byte provenance, and `src/mapping.js` owns text lookup, serialization, import/composition, and diagnostic remapping.

`src/toolchains.js` resolves configured absolute overrides or one unambiguous canonical PATH executable, runs a bounded version command, and returns its exact real path and captured version. Alongside language compilers/runtimes, browser Wasm defines exact WABT 1.0.36 and Chrome/Chromium 152.0.7977.82 contracts through `SEMANTIFOLD_WASM_VALIDATE` and `SEMANTIFOLD_CHROMIUM`. `src/acceptance.js` validates all artifacts and ordered stages before filesystem mutation, materializes only safe generated paths in a unique temporary directory, invokes exact executable/argument arrays without a shell, fixes `LANG`, `LC_ALL`, and `TZ`, captures output, distinguishes discovery/version/launch/timeout/nonzero failures, records the precise failed stage, and removes the directory. The browser-specific acceptance owner additionally serves a materialized artifact directory on loopback under strict CSP and owns the headless browser process group. No runner performs tool installation or runtime download.

## Browser WebAssembly target

`src/backends/wasm.js` consumes the unchanged semantic module and directly emits core WebAssembly binary version 1. It owns signed-i64 arithmetic traps, canonical i32 Booleans, UTF-8 literal/data layout, fixed memory, the private checked scratch allocator, semantic call-depth guards, the `semantifold.browser.v1` import/export ABI, binary section/index construction, and path-sensitive resource analysis. These are target concerns and add no Wasm nodes, pointers, traps, imports, memory, or JavaScript values to `src/semantic/`.

Generation first bounds the caller graph before recursive shared validation, checks known i64 operations module-wide, then performs entry-reachable resource validation. It builds deterministic literal and function indexes, emits all bytes with contiguous `SemantifoldByteMapping` ranges, and validates the completed module with the host standard WebAssembly API. Only then does it construct the ordered module/map/loader/HTML set and frozen ABI metadata. The generated JavaScript starts native streaming immediately while inspecting a response clone, keeps host import behavior locked until import signatures, fixed memory, exports, and absence of a start section pass, and cannot execute semantic operations itself. See the [browser WebAssembly target](webassembly.md).

## Future standard-library portability

Standard-library portability is a planned extension of these layers, not current behavior. A frontend will substitute a source-language **language compatibility stdlib/facade** only after parser-backed module resolution proves the native library and symbol identity. The facade is portable executable source that enters the same frontend and semantic layers as application code. It calls a versioned **canonical Semantifold stdlib contract/capability**, never a target API or pair-specific bridge.

Artifact generation will compile the application and only its used compatibility modules, then link only the required **target host provider/native binding** modules. Providers implement canonical capabilities with the target's genuine native stdlib behind a protected host-native boundary unavailable to ordinary application and facade code; that isolation also prevents same-language generation from recursively selecting its own compatibility facade. Contract and target validation must finish before any artifact is exposed. Unsupported source identity, source APIs, target capabilities, or semantic mismatches produce located diagnostics rather than partial output.

Generated target code may preserve source API class or function names in a collision-safe compatibility namespace or import alias while using valid target syntax. A later backend may replace a facade/provider path with direct idiomatic lowering only when equivalence is proven; it is never the correctness baseline. Linking, tree-shaking, contract precision, namespace rules, and the full compile flow are defined in the [authoritative standard-library portability design](standard-library-portability.md).

## Round trips

The tested semantic round trip is source → semantic module → generated source → equivalent semantic module. It preserves modeled meaning, not original spelling, string quotes/escapes, comments, whitespace, visibility, braces, or formatting. Parsed generated-source locations still refer to generated source, while `SemantifoldMapping` explicitly relates generated ranges back to semantic and original ranges. `number` in JS/TypeScript remains deliberately narrowed to semantic `integer` even though those languages permit fractional and special numeric values; only safe integer literals can enter the representation. String values contain complete Unicode scalar values, never source interpolation or lone UTF-16 surrogates, and each backend escapes that value without concatenating source fragments.

Frontend source capabilities and backend target capabilities are intentionally separate. Adapters recognize parser-native syntax and retain a transient parser-neutral operation intent only until shared validation resolves identifier and call types. Successful parsing replaces that intent with one of the closed typed operations below before the public module is returned. Invalid operands point to the offending nested expression; mismatched equality points to the unequal operand; and a non-Boolean condition has its own stable diagnostic.

| Result | Closed semantic operations |
| --- | --- |
| `integer` | `IntegerAdd`, `IntegerSubtract`, `IntegerMultiply`, `IntegerNegate` |
| `boolean` from integers | `IntegerEqual`, `IntegerNotEqual`, `IntegerLessThan`, `IntegerLessThanOrEqual`, `IntegerGreaterThan`, `IntegerGreaterThanOrEqual` |
| `boolean` from booleans | `BooleanNot`, `BooleanAnd`, `BooleanOr`, `BooleanEqual`, `BooleanNotEqual` |
| `boolean` from strings | `StringEqual`, `StringNotEqual` |
| `string` | `StringConcat` |

Binary operands evaluate left to right. `BooleanAnd` and `BooleanOr` are short-circuit operations. Equality accepts only two operands of the same supported scalar type and means scalar value equality. Semantic integers are mathematical integers with one unsigned zero; IEEE-754 signed zero is not a distinct semantic value. Backends map meaning rather than copying syntax: PHP concatenation is `.`, Java string equality is `.equals`, JavaScript/TypeScript/PHP equality is strict, and other operations use their target's matching native construct. Because supported operations cannot otherwise distinguish signed zero, JavaScript and TypeScript canonically stringify observable scalar output when a module contains integer negation or multiplication. Their frontends unwrap that exact parser-native output scaffold during generated-source reparse, retaining the original operation tree without constant folding. Every emitted operation is conservatively parenthesized; generated-source reparsing reconstructs the same semantic tree.

A source-valid semantic name can be rejected for a target reserved word, and a safe semantic integer can be rejected by Java's narrower `int` range. Java validates literal-only integer operation trees with exact mathematical integers without folding the IR, rejecting known results outside signed 32-bit `int`. Kotlin rejects known results outside the semantic safe range and routes dynamic arithmetic through private `Math.*Exact` helpers followed by the same bound check. C# performs the same proof against signed 64-bit and emits an exact `checked(...)` wrapper for every integer arithmetic/negate operation while the project also enables overflow checking. Go performs the signed-64-bit proof without folding, but non-literal runtime overflow retains native `int64` wrap behavior and remains outside the portable result guarantee.

## Blocks, flow, and bindings

Blocks preserve source order, evaluation order, and lexical nesting. Validation walks each statement once in order: an unconditional return makes every following statement in that block unreachable, and an `if` returns on all paths only when both its consequent and present alternate do. A non-void function must end every reachable path in an explicit return; optional alternates and empty blocks are valid only when later control flow remains complete. Entry points may not return a value.

Function identity is resolver-owned and exposed as deterministic module-local `function:N` IDs, never parser objects or trusted caller numeric IDs. A complete module signature pass precedes every body, so direct recursion and unambiguous forward or mutual references resolve consistently. Calls bind that identity and exact ordered signature; backend validation rechecks caller-supplied bindings before emission. Each provenance pass creates symbol records for functions, parameters, and locals, records a function symbol's semantic declaration identity, and resolves identifier reads, assignment targets, and calls through lexical function/branch/entry scopes. Module callables, parameters, and locals share one no-shadowing namespace; repeated names are rejected even across disjoint branches in this initial capability. Nested-block declarations do not escape their block. Initializers are validated before declaration and assignment right-hand expressions before the target update, preserving evaluation order and making self-reference a use-before-declaration error.

Task006 adds recursive `ListType` and `MapType` value types while retaining scalar `TypeReference` leaves. Lists are finite, homogeneous, ordered, zero-based, and duplicate-preserving; maps are finite homogeneous string-key associations with source-ordered initializer diagnostics but no semantic iteration order. Literal/index/lookup/size nodes are traversed recursively for validation, provenance, symbol resolution, and mapping. Static literal propagation proves bounded reads; only an exact source operation with absence failure can admit an otherwise dynamic read. The IR has no optional result, mutation, deep-freeze promise, or object/record interpretation. Backend capability and target factory/key restrictions are checked before writer or artifact construction.

Task007 adds explicit `OptionalType`, presence/absence construction, simple-identifier presence tests, and proof-checked unwrap. Presence facts are branch-local and invalidated conservatively by assignment. Task008 adds ordered `ForEachStatement` over lists with one immutable body binding and nearest-loop control; it never exposes map order. Task009 adds parser-neutral nominal `RecordDeclaration`, `RecordField`, `RecordType`, `RecordConstruction`, and `MemberRead` values. Declaration and field identities, ordered arity, nominal type equality, direct-recursion rejection, mediated-recursion representation, and member resolution live in the semantic validator; parser-specific class trees remain in frontends and target declaration/access syntax remains in backends. Task011 adds `ErrorDeclaration`, `ErrorType`, `ErrorConstruction`, `RaiseStatement`, `TryStatement`, immutable `CatchBinding`, and `ErrorMessageRead`. Exact handler identity removes only its matching error from a protected block's escaping set; unmatched errors and errors raised by the handler propagate. A raise, return, break, or continue ends the current block path, while a caught path may resume after the try. Task012 keeps generic typing in this same hub: declaration scopes own stable parameter IDs, recursive validation rejects free/raw/wrong-arity applications, and argument-only first-order unification recursively gathers evidence from list/map/optional argument structure before contextually validating evidence-free nested values after the substitution is complete. Shared recursive substitution and variable detection close call returns, record construction fields, and member reads without mutating declarations. Externally supplied call resolutions must contain dense ordered inferred type arguments, including every nested generic-record identity array. Frontends use those same operations only for parser conversion and conservative syntax classification from parser-known arguments or explicit applications; they preserve an optional binding as a whole when it is direct generic evidence, and never use the expected return type. For parser-known context, a present nonoptional value against `Optional<X>` contributes evidence to `X`, two optionals recurse structurally, and an optional actual against plain `T` remains the whole inferred type. PHP call conversion may use that rule to close recursive documented parameter context from sibling arguments, but any variable left open must have an exact ID owned by the caller's lexical declaration. PHP optional generic-record access becomes a semantic unwrap only through the existing branch-local presence proof. Program rekeying qualifies both declaration and parameter IDs. Type parameters and every reference are ordinary provenance nodes/symbols; target backends receive only canonical types and either emit native syntax or exact documented syntax. No source/target pair adapter or standard-library capability is introduced. Task013 adds no node or validation rule: its spec-only structural comparator excludes locations, provenance, and regenerated declaration IDs while preserving every other modeled field, and its five-by-five round trips freeze the historical Tasks001–008 original-five boundary.

## Provenance and generated mappings

Frontend offsets remain parser-owned. Babel token positions, php-parser nodes/tokens, Prism byte locations/comment carriers, Lezer syntax nodes, and Tree-sitter Python/C#/Go/C/CPP/Rust/Swift/Kotlin named and anonymous nodes provide exact function, parameter, local, type, assignment, literal, call, branch, error declaration/construction, catch type/binding, message read, and operator ranges. Every Tree-sitter adapter traverses every child, rejects propagated error/missing recovery, and never substitutes source-text parsing after a rejected tree node. Error declarations and catches receive their own symbols; construction/type and catch-binding message-read references resolve through the same deterministic provenance graph. The JavaScript/TypeScript adapter indexes Babel tokens once by start offset, using direct identifier lookup and bounded binary-search token lookup instead of rescanning the full token stream per semantic node. Source normalization converts only coordinates; it never normalizes source content. CRLF and lone CR count as line breaks and parser coordinates become verified UTF-16 offsets.

Each semantic node carries a JSON-safe source-provenance association through reorder, insertion, deletion, cloning, and serialization. Generation rebuilds canonical paths and node/symbol identities from current traversal and validates any serialized caller provenance before use; aggregate path/kind coincidence is never used to associate a different node. Shared caller objects receive deterministic occurrence records keyed by current JSON Pointer, so reused parameters, types, expressions, and valid statements do not collapse distinct emitted locations. Malformed caller registries, including empty source filenames, are discarded before canonical source fallback. This permits legacy and multi-source caller IR while preventing duplicate/stale IDs, mismatched source ownership, or out-of-bounds ranges from becoming semantic authority. The source-aware writer makes all output spans explicit, retains every contextual origin range across composition boundaries, and leaves no coarse legacy emitter path. Rich maps are frozen and indexed after validation; generated, original, node, and symbol queries include contextual related provenance without duplicate spans. See [source provenance and mappings](source-maps.md).

## Task019 CPP integration

`src/frontends/cpp.js` independently consumes official CPP snapshots and validates exact qualified types, condition clauses, inline support and CPP ordered regions. `src/backends/cpp.js` emits one mapped `program.cpp`; `cpp-runtime.js` owns fixed C++20 libstdc++ support and `cpp-validation.js` proves known owned-value sizes. C and CPP reuse `ordered-expressions.js` for occurrence planning/signatures and `native-validation.js` for bounded graphs, with the owning language preserved in diagnostics. The CPP frontend compares complete CPP CST structure against its canonical CPP output; it never calls the C frontend. The private runtime explicitly selects its official grammar and exports only frozen parser-neutral values. No semantic IR, standalone package identity, parser export, artifact contract or standard-library architecture is expanded. See the [CPP profile](cpp.md).

## Rust ownership and Cargo artifacts

Task020 adds `rust` through the same role registry, semantic language/provenance union, scalar tables and identifier validation. Its dedicated frontend adapter calls the existing private `parseCst(source, "rust")` boundary; only schema-1 recursively frozen plain data crosses the native runtime boundary. The root binding stays 0.25.1 and the private binding stays 0.21.1 with exact official Rust grammar 0.23.1. There is no pairwise dispatch or new semantic node.

The Rust reader accounts for every parser edge and compares all helper CST fields and tokens with exact target-owned support. It records clone and borrow occurrences privately, resolves scalar operations through shared validation, then checks moves in left-to-right evaluation order and joins continuing branch paths. Generated clones never repair illegal source moves. Only exact string construction, clones, concat borrows and print/overflow helpers collapse into existing scalar expressions and statements; arbitrary macros and source-text reparsing are forbidden.

The Cargo backend validates the complete graph, types, flow, bindings, reserved/scalar/helper collisions, fixed paths, known numeric/string bounds, source length and expanded CST depth before creating a writer or returning artifacts. A size/depth preflight follows the actual emission rules, including String borrow wrappers. The ordered set is synthetic manifest, synthetic Cargo-qualified format-4 lock, mapped entry source. Generation has no filesystem, network or compiler effects. Native left-to-right operands and short-circuit operators need no ordered temporary lowering. Clones, borrow punctuation and support bodies carry synthetic provenance related to the original nodes; copied identifiers, literals, call and operator tokens retain their original ranges.

Rust/Cargo discovery requires the exact qualified 1.98.1 commits and Linux x86-64 host; the verbose Cargo OS/library lines may differ across the qualified Ubuntu bases. Offline acceptance supplies an empty Cargo home and the exact compiler path, separates check/build diagnostics from direct binary and Cargo-run output, and verifies all original artifact hashes after both profiles. Host allocation, stack and output failures remain host failures under `panic = "abort"`, outside portable control flow. [Rust](rust.md) records the complete contract and qualification.
