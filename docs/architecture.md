# Architecture

Semantifold has three explicit layers.

1. Frontend adapters in `src/frontends/` invoke mature language parsers and translate only recognized syntax. Babel owns JavaScript and TypeScript parsing, `php-parser` owns PHP, Prism owns Ruby, and Lezer owns Java. Their AST/CST objects never appear in the public API. Adapters enumerate supported children and reject every other parser node; filtering syntax away is not a normalization strategy. Prism node offsets and comment byte ranges are converted from UTF-8 to JavaScript UTF-16 offsets before semantic location construction and metadata source slicing.
2. `src/semantic/` defines the shared JSDoc-typed discriminated representation and one-based, filename-bearing UTF-16 source locations. `provenance.js` indexes exact source content, deterministic semantic paths/node IDs, resolved symbol IDs, parser-token subranges, and closed source/derived/synthetic origins without exposing parser objects. Scalar types are exact `integer`, `boolean`, or `string` references. Literal nodes carry JavaScript-safe integer, primitive boolean, or parser-decoded Unicode scalar values. `LocalDeclaration` carries a name, explicit type, mutability bit, initializer, and declaration location; `AssignmentStatement` carries a simple identifier target, right-hand expression, and statement location. The remaining constrained nodes are module, function, parameter, entry point, if, return, print, identifier, binary expression, and two-argument call.
3. Source backends in `src/backends/` validate their semantic capabilities before emitting target syntax. Shared validation owns restricted task-002 statement prefixes, recursively complete expressions, function signatures, lexical binding scopes, mutability, declaration-before-use, and strict condition/return/argument/initializer/assignment types. Target-specific validation adds identifier rules, entry-scaffolding name collisions, Java's signed 32-bit `int` literal range, and target string escaping. Every emitter writes through `SourceWriter`; semantic tokens, target anchors, and synthetic layout are mapped as they are emitted. A backend either returns a complete executable program or raises `UNSUPPORTED_CAPABILITY`; it never silently drops nodes or lets an emitter discover malformed shape through a `TypeError`.

`index.js` is the public boundary. `parse({language, filename, source})` dispatches to an adapter. `generate({language, module})` validates and returns the compatibility source string. `generateArtifact(...)` uses the same emission path and returns code plus rich and v3 mappings. `src/mapping.js` owns validated lookup, deterministic serialization, mapping import/composition, and diagnostic remapping.

## Round trips

The tested semantic round trip is source → semantic module → generated source → equivalent semantic module. It preserves modeled meaning, not original spelling, string quotes/escapes, comments, whitespace, visibility, braces, or formatting. Parsed generated-source locations still refer to generated source, while `SemantifoldMapping` explicitly relates generated ranges back to semantic and original ranges. `number` in JS/TypeScript remains deliberately narrowed to semantic `integer` even though those languages permit fractional and special numeric values; only safe integer literals can enter the representation. String values contain complete Unicode scalar values, never source interpolation or lone UTF-16 surrogates, and each backend escapes that value without concatenating source fragments.

Frontend source capabilities and backend target capabilities are intentionally separate. A source-valid semantic name can be rejected for a target reserved word, and a safe semantic integer can be rejected by Java's narrower `int` range. Shared typing requires integer operands for `+`, `-`, and `>`, makes `>` boolean, requires boolean conditions, and checks exact return and call-argument types. These failures retain their source expression or declaration-owner location. Arithmetic-result overflow is not normalized across runtimes and remains unresolved beyond the accepted execution cases.

## Bindings and restricted statement order

Binding identity is resolver-owned and exposed as deterministic module-local string IDs, never parser objects or trusted caller numeric IDs. Each validation/provenance pass creates symbol records for functions, parameters, and locals and resolves identifier reads, assignment targets, and calls through lexical function/branch/entry scopes. Module callables, parameters, and locals share one no-shadowing namespace; repeated names are rejected even across disjoint branches in this initial capability. Branch-local declarations do not escape their branch. Initializers are validated before declaration and assignment right-hand expressions before the target update, preserving evaluation order and making self-reference a use-before-declaration error.

## Provenance and generated mappings

Frontend offsets remain parser-owned. Babel token positions, php-parser nodes/tokens, Prism byte locations/comment carriers, and Lezer syntax nodes provide exact function, parameter, local, type, assignment, literal, call, and operator ranges. Source normalization converts only coordinates; it never normalizes source content. CRLF and lone CR count as line breaks and Ruby byte offsets become UTF-16 offsets.

Generation rebuilds canonical node/symbol identities and validates any serialized caller provenance before use. This permits legacy and multi-source caller IR while preventing duplicate/stale IDs or out-of-bounds ranges from becoming semantic authority. The source-aware writer makes all output spans explicit and leaves no coarse legacy emitter path. See [source provenance and mappings](source-maps.md).

Task 002 deliberately retains statement arrays instead of introducing general semantic blocks. Only local declaration/assignment prefixes before the existing terminal function `if`, branch return, and entry print are representable. Roadmap task 004 owns reusable `Block` nodes, arbitrary supported statement sequencing, nested/general conditionals, reachability, and return completeness.
