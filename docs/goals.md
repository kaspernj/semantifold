# Goals

Semantifold's long-term goal is a language-neutral toolkit for understanding, transforming, generating, and eventually executing programs through a shared high-level semantic representation. The representation should make types, control flow, calls, declarations, diagnostics, and source provenance understandable without exposing a language parser's private tree.

The current source tree proves one minimal Tasks 001–004 vertical slice across thirteen registered languages: PHP, Ruby, JavaScript, TypeScript, Java, Kotlin/JVM, strictly annotated Python, canonical C#, bounded Go, C17, C++20, Rust edition 2021, and Swift. The original five additionally have the delivered Task 013 acceptance gate for the combined Tasks 001–008 profile, Task 009 nominal closed records, Task 010 explicit acyclic multi-source semantic programs, Task 011 exact nominal typed unchecked errors, and Task 012 invariant unbounded function/record type parameters with closed applications and argument-only first-order call inference. Task 012's PHP recursive-generic documentation correction is merged through PR #40 at `b12ec507d9e04dd57fbb4305129b21625d191a74`. The Task 014 candidate adds a separate homogeneous insertion-ordered map type and immutable key/value pair iteration for that same cohort while preserving ordinary unordered maps. The source tree includes versioned source provenance, deterministic semantic node/symbol identity, range-based generated mappings, Source Map v3 interop, composition, and diagnostic remapping across those bounded profiles. The published `semantifold@0.3.0` release predates these additions. Neither the source tree nor that release provides a general analyzer, transformation API, interpreter, optimizer, implicit project/package discovery, debugger integration, coverage remapping, or lossless formatter.

The long-term product direction includes bounded standard-library portability through [language compatibility stdlib/facades, canonical Semantifold stdlib contracts/capabilities, and target host providers/native bindings](standard-library-portability.md). That direction is incremental and versioned; it does not promise arbitrary standard-library coverage or arbitrary-application translation. The `0.3.0` release has no imports, classes or methods, loops, optional values, typed errors, resources, host APIs, or stdlib portability.

Other roadmap candidates include a versioned fuller semantic schema, more scalar and compound types, expressions and statements, user-authored transformations, richer backend capability negotiation, cross-language stack/coverage presentation, and a semantic interpreter. Task 014 now owns the only observable ordered-map iteration profile; it deliberately does not assign order to ordinary Task 006 maps or broaden Task 008 list loops. LLVM, general Wasm source support, JVM bytecode, package-manager resolution, package publication automation, and production TensorBuzz changes remain outside the current release.
