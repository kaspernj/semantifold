# Goals

Semantifold's long-term goal is a language-neutral toolkit for understanding, transforming, generating, and eventually executing programs through a shared high-level semantic representation. The representation should make types, control flow, calls, declarations, diagnostics, and source provenance understandable without exposing a language parser's private tree.

The current source tree proves one minimal Tasks 001–004 vertical slice across thirteen registered languages: PHP, Ruby, JavaScript, TypeScript, Java, Kotlin/JVM, strictly annotated Python, canonical C#, bounded Go, C17, C++20, Rust edition 2021, and Swift. The original five additionally have the delivered Task 013 acceptance gate for the combined Tasks 001–008 profile, Task 009 nominal closed records, Task 010 explicit acyclic multi-source semantic programs, Task 011 exact nominal typed unchecked errors, and Task 012 invariant unbounded function/record type parameters with closed applications and argument-only first-order call inference. Task 012's PHP recursive-generic documentation correction is merged through PR #40 at `b12ec507d9e04dd57fbb4305129b21625d191a74`. Task 014 is delivered through PR #41 at corrected head `e54047a2988b776fa5ea9ae8ab8bdabc0b56642f` and merge commit `9f3a05a5ab8e25879f2323d032c8aa9f5ec4a702`, with green exact-head checks, retired monitoring, and completed post-merge acceptance. Task 032 is delivered through PR #42 and merge commit `e6889212a57d4d0820b9c5cd3ad21b0ef8cc2c9e`. Task 033 was delivered through PR #43 at exact head `98a9fa5bb1048fbe44e798acdefd65b9d6d2560e` and merge commit `f2e7f44aa8065f785c314b66e1f1d55992b7c998`. Task 034 is implemented locally with compiler-authorized effects and explicit owned-resource lifetime for the same cohort; independent review, TensorBuzz CI, and merge remain coordinator-owned. The source tree includes versioned source provenance, deterministic semantic node/symbol identity, range-based generated mappings, Source Map v3 interop, composition, and diagnostic remapping across those bounded profiles. The published `semantifold@0.3.0` release predates these additions. Neither the source tree nor that release provides a general analyzer, transformation API, interpreter, optimizer, implicit project/package discovery, debugger integration, coverage remapping, or lossless formatter.

The long-term product direction includes bounded standard-library portability through [language compatibility stdlib/facades, canonical Semantifold stdlib contracts/capabilities, and target host providers/native bindings](standard-library-portability.md). That direction is incremental and versioned; it does not promise arbitrary standard-library coverage or arbitrary-application translation. The `0.3.0` release has no imports, classes or methods, loops, optional values, typed errors, resources, host APIs, or stdlib portability.

Other roadmap candidates include a versioned fuller semantic schema, more scalar and compound types, expressions and statements, user-authored transformations, richer backend capability negotiation, cross-language stack/coverage presentation, and a semantic interpreter. Task 014 owns the only observable ordered-map iteration profile; it deliberately does not assign order to ordinary Task 006 maps. Task 032 separately owns the exact condition-controlled loop profile and resolved control identities across every supported loop kind without adding standard-library behavior. Task 033 owns only the closed, single-module reference-class profile. Task 034 owns the bounded unversioned single-module effect/ownership/close foundation and deliberately excludes public host APIs and general effects; versioned contracts, facades, providers, and linking remain in Tasks 035–037. LLVM, general Wasm source support, JVM bytecode, package-manager resolution, package publication automation, and production TensorBuzz changes remain outside the current release.
